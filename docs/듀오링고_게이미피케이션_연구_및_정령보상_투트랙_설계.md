# 듀오링고 게이미피케이션 연구 → 정령·보상 투트랙 적용 설계

> 작성: 박소연(시니어 프로덕트 디자이너) · 강지후(UX 리서처) 공동.
> 목적: ① 정령(EXP) 성장과 ② 재화(포인트/P) 보상이라는 **두 트랙을 사용자가 즉시·동시에 인지**하도록 완료/정령/셸 화면을 재설계하고, 듀오링고식 지속 참여 유도(스트릭·즉각 피드백·손실회피)를 itsme 맥락에 이식한다.
> 원칙: 신규 헤비 의존성 0, 순수 CSS·자체 SVG 우선, 로직(API·a11y) 보존, 오버엔지니어링 지양. 기존 [모바일 개편 트래킹](모바일_개편_트래킹.md)·[토스 UX/UI 방법론](토스_UXUI_방법론_연구.md)과 정합.

### 1.3 핵심 인사이트 (구현에 직접 반영)

1. **XP는 "공통 화폐"로서 모든 행동을 즉시 보상하고 다른 메커닉을 연결한다** (Trophy). itsme의 EXP는 정령 성장의 공통 화폐인데 **완료 순간 증가량이 안 보인다** → 즉각 피드백 손실.
2. **이중화폐 분리**: 듀오링고는 XP(성장·소비불가) ↔ Gem(소비화폐)을 색·아이콘·맥락으로 명확히 분리. itsme는 EXP(성장) ↔ 포인트(소비)인데 완료화면이 **포인트만 크게** 보여줘 투트랙이 한눈에 안 들어옴.
3. **스트릭 = 리텐션 엔진**: freeze 있으면 7일 후 평균 17.19일 vs 없으면 11.62일(+48%). 손실회वि 비대칭(180일 잃기 싫음 > 181 얻고 싶음). itsme `streak`이 **백엔드에만 있고 화면에 전무**.
4. **보상예측오류**(PLOS ONE): 예측 못한 보상이 학습·복귀를 더 강화 → 가끔 가변 보너스가 고정 보상보다 강력.
5. **즉각성**: 보상 신호가 행동과 시간적으로 밀착할수록 강력(lesson 닫기 전 XP 지급).
6. **계층적 설계**: 신규(즉시 성취)·중기(지킬 스트릭)·장기(희귀 목표)가 각기 다른 세그먼트를 리텐션. itsme는 우선 신규·중기(EXP 즉각+스트릭)에 집중.

## 2. 진단 — itsme 현재 보상 화면의 문제 (QA 관점)

코드 근거: [PanelistMobile.tsx](../apps/frontend/src/features/PanelistMobile.tsx) `CompleteStage`(~L1855), `PetStage`(~L1132), 백엔드 [response.service.ts](../apps/backend/src/modules/response/response.service.ts) `completeResponse`.

| 코드 | 문제(현상 → 갭)                                                                                                                                                  | 듀오링고 원칙 위반            |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| P0-A | **완료화면이 `+{pointsAwarded}P`(재화)만 88px로 크게 표시.** EXP 획득량(델타)은 아예 없고 결과 `Lv.5 · 알`만 작은 요약으로 → **정령 트랙이 보상으로 인지 안 됨** | ② 진척·④ 이중화폐 즉각 피드백 |
| P0-B | 백엔드는 `expGained`·`leveledUp`·`streak`을 계산하지만 **프론트로 전달 안 함**(`Reward` 타입에 `pointsAwarded`+결과 pet만)                                       | ② 즉각 피드백 손실            |
| P0-C | **스트릭이 화면 어디에도 없음**(백엔드 `pet.streak` 존재). 손실회피 리텐션 엔진 미가동                                                                           | ⑧ 손실회피 전무               |
| P1-D | 완료화면 두 요약(`정령`/`누적 포인트`)이 **동급·무채색 박스**라 트랙 구분이 약함. 색·아이콘 분리 없음                                                            | ④ 소유 구분 약함              |
| P1-E | 레벨업이 일어나도 **별도 축하 없음**(그냥 숫자만 바뀜). 진화(Lv10) 외 중간 레벨업 무피드백                                                                       | ② 성취 모멘트 누락            |
| P2-F | 보상이 **항상 고정**(콘페티만). 가변 보너스(예측오류) 없음                                                                                                       | ⑦ 불확실성 미활용             |

### 핵심 결론

> **완료화면을 "투트랙 보상 카드"로 재설계한다.** 한 화면에서 (1) 정령 EXP 트랙(+EXP 델타 → 진척바 애니메이션 → 레벨/진화), (2) 재화 트랙(+P → 누적 잔액)을 **색·아이콘으로 분리해 동시에** 보여준다. 여기에 (3) 스트릭 칩을 추가해 손실회피 루프를 가동한다.

## 3. 적용 설계 (디자인 디테일)

### 3.1 투트랙 보상 카드 (완료화면 재설계)

```
┌─────────────────────────────────┐
│         (정령 SVG + 버스트)         │   ← 축하 헤더(유지)
│        응답을 완료했어요              │
│                                   │
│   ┌─── 정령 트랙(보라) ──────────┐    │   ← Track A: 성장
│   │ ✨ +30 EXP                  │    │      아이콘=Sparkles, 보라 accent
│   │ ▓▓▓▓▓▓▓░░░ Lv.5            │    │      진척바 애니메이션(0→채움)
│   │ 다음 레벨까지 40 EXP          │    │
│   └───────────────────────────┘    │
│   ┌─── 포인트 트랙(블루/Gem) ─────┐   │   ← Track B: 재화
│   │ 💎 +1,000 P                │    │      아이콘=Gem, 블루 accent
│   │ 누적 4,230 P                │    │
│   └───────────────────────────┘    │
│                                   │
│   🔥 3일 연속 참여 중                │   ← 스트릭 칩(손실회피)
│                                   │
│      [ 다음 설문 보기 ]              │
└─────────────────────────────────┘
```

**디자인 원칙**

- **색 분리**: 정령 트랙 = `--color-primary`(보라) 계열 surface, 포인트 트랙 = `--color-accent-blue`(블루)+Gem. 두 트랙이 색만으로 즉시 구분.
- **즉각성**: 진입 시 +EXP 숫자가 먼저 팝 → 진척바가 이전 값에서 새 값으로 차오르는 애니메이션(0.6s spring) → 레벨업 시 Lv 배지 플립+버스트. (reduced-motion 시 즉시 최종상태)
- **레벨업 강조(P1-E)**: `leveledUp`이면 정령 트랙에 "레벨 업! Lv.4 → Lv.5" 강조 라인 + 살짝 큰 버스트.
- **스트릭(P0-C)**: 🔥 + "N일 연속". `streak>=2`일 때만 노출(1일은 비노출로 과장 방지). 위계는 보조(13px).
- **가변 보너스(P2-F, 후순위 옵션)**: 일정 확률 또는 마일스톤(예: 5의 배수 완료)에서 "보너스 +EXP" 가변 노출. 1차 구현은 자리만 잡고 로직은 단순 유지.

### 3.2 정령 탭(PetStage) 보강

- **스트릭 라인 추가**: 레벨/EXP 근처에 🔥 스트릭을 상시 노출(없으면 "오늘 첫 참여로 시작해요" 유도). 손실회피 + 소명.
- **투트랙 라벨 명확화**: EXP는 "정령 성장", 포인트는 "교환 가능"이라는 의미가 드러나도록 마이크로카피.

### 3.3 셸(topbar) — 이미 Gem 잔액 버튼 존재

- 포인트(💎) 잔액 버튼은 유지. (EXP/스트릭은 정령 탭·완료화면이 주 노출 지점이라 탑바 과밀 회피.)

### 3.4 백엔드 보상 계약 확장 (P0-B)

`CompletionOutcome.pet`에 다음을 추가(비파괴적, 기존 필드 유지):

- `expGained: number` — 이번 응답으로 얻은 EXP 델타(`computeExpFromSurvey` 결과를 별도 보존).
- `leveledUp: boolean` + `prevLevel: number` — 레벨 상승 여부/이전 레벨.
- `streak: number` — `applyStreak` 결과.

프론트 `Reward` 타입도 동일 확장. `alreadyCompletedOutcome`은 `expGained:0, leveledUp:false`로.

## 5. 검증·리스크

- **a11y 보존**: `aria-live`로 EXP/포인트/레벨업/스트릭 변화를 스크린리더에 고지. 색에만 의존하지 않게 아이콘+라벨 병기.
- **테마 정합**: 앞선 M7/M8 교훈대로 신규 토큰은 `.pm-root` 라이트/다크에 모두 잠가 OS 누수 방지.
- **비파괴**: 백엔드 계약은 필드 추가만(기존 소비자 안전). 프론트는 옵셔널 필드로 받아 구버전 응답도 안전.
- **오버엔지니어링 회피**: 사회·희소·freeze는 자리만, 핵심(투트랙 즉각 피드백 + 스트릭 가시화)에 집중.
