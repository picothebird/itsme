# 모바일 개편 진행도 트래킹 (Toss 이상 품질 목표)

> 대상: 패널리스트 모바일 앱([PanelistMobile](../apps/frontend/src/features/PanelistMobile.tsx) + `.pm-*` 스타일 [App.css](../apps/frontend/src/App.css)).
> 검수자: 박소연(시니어 프로덕트 디자이너, ex-Toss) · 강지후(UX 리서처).
> 검증: 브라우저 자동 클릭은 로그인 연속 애니메이션으로 타임아웃 → lint/build/get_errors/코드 추론으로 검증.
> 원칙: 신규 헤비 의존성 0, 순수 CSS·자체 SVG 우선, 오버엔지니어링 지양, 로직(API·a11y) 보존.

### M-라운드 3 (문서 재크리틱 — 누락 페이지·기능 발견)

> 트래킹 문서 자체를 재검수한 결과, **진입 플로우(로그인·온보딩·부화)와 다수 상태 화면이 인벤토리에서 통째로 누락**돼 있었음. 더 심각한 건, 누락됐던 공용 셸([PanelistApp](../apps/frontend/src/features/PanelistApp.tsx))이 G-6에서 제거한 줄 알았던 **흰 박스 "잇츠미" 헤더를 그대로 사용** 중이라는 점(G-6 회귀/미완). 아래는 발견 즉시 등재한 후속 개편 항목.

| ID   | 영역            | 우선 | 크리틱(현상태 → 갭)                                                                                                                                    | 개편                                                          | 상태 |
| ---- | --------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- | ---- |
| M3-1 | 문서            | P0   | 진입 플로우(L/OB/H)·상태화면(LD/E/ERR/W)이 인벤토리에 **전무**                                                                                         | 인벤토리에 7개 코드 추가·보강                                 | ☑    |
| M3-2 | L/OB/H (SH)     | P0   | `PanelistApp` topbar가 옛 `pm-topbar__title`("잇츠미")+`pm-topbar__spacer` 구조 → **사용자가 빼라던 흰/검은 박스 헤더가 진입 화면에 잔존**(G-6 미적용) | G-6 브랜드 락업(SVG 로고+`itsme`) 셸을 `PanelistApp`에도 적용 | ☑    |
| M3-3 | H (부화)        | P1   | 부화 화면이 자체 SVG 정령([PetCreature], G-7) 대신 옛 `pm-hatch__spirit` 블롭 div 사용 → 캐릭터 일관성 깨짐                                            | 부화 정령을 `PetCreature`로 교체(블롭 CSS 제거)               | ☑    |

| M3-5 | OB (온보딩)     | P2   | 진행 점을 `ProgressDots` 컴포넌트가 아닌 `pm-dot` 직접 마크업으로 중복 구현                                                                            | 공용 컴포넌트로 통일(컴포넌트 추출 필요)                      | ☐    |
