# 글로벌 리서치 플랫폼 심층 벤치마크 분석 및 잇츠미(itsme) 적용 설계서

> **문서 목적** — 전 세계 상위 리서치 기업과 오픈서베이가 제공하는 서비스 전 영역을 리서치 업무 흐름(기획→설계→표본설계→스크리닝→필딩→품질관리→집계→분석→리포팅→정산) 관점에서 해부하고, 이를 잇츠미의 **백오피스(리서처)** 와 **유저 앱(응답자)** 두 개의 완전히 분리된 서비스로 어떻게 녹여낼지 단계적으로 설계한다.
>
> **작성일** 2026-05-31 · **버전** v1.0 · **상태** 기획 확정 대기
>
> **방법론 및 한계** — 본 문서의 기업별 기능·모델 서술은 공개된 제품 문서·업계 표준(ESOMAR, GRIT, AMA Gold Top 50)·일반적으로 알려진 제품 구조에 기반한다. 매출·패널 규모 등 수치는 시점에 따라 변동하는 **지표(indicative)** 이며 의사결정의 절대 근거가 아니라 상대적 포지셔닝 이해용이다. 잇츠미 적용 설계는 현재 코드베이스(React 19 / Vite / Express / 메모리 스토어 MVP)를 기준으로 한다.

## 0. 핵심 결론 요약 (Executive Summary)

1. **백오피스와 유저사이드는 별개의 두 제품이다.** 글로벌 플레이어 누구도 "연구자 콘솔"과 "패널 앱"을 같은 화면·같은 진입점에서 섞지 않는다. 잇츠미도 도메인·인증·코드·디자인 시스템까지 물리적으로 분리해야 한다. (현재의 역할 토글/응답 모달은 데모 잔재이므로 제거)
2. **리서치는 '설문'만이 아니다.** 상위 업체의 본질은 ① **패널(모집단) 자산**, ② **표본 설계·스크리닝·쿼터 관리**, ③ **필딩 운영·품질관리**, ④ **분석·리포팅 자동화** 의 4축이다. 잇츠미가 단순 설문 도구를 넘어 "리서치 운영 플랫폼"이 되려면 이 4축을 갖춰야 한다.
3. **잇츠미의 차별 포인트는 두 가지 리서치 유형의 공존이다.**
   - **즉시참여형(Self-serve survey)** — 유저가 피드에서 바로 응답 → 즉시 보상. (현재 구현된 스와이프 덱)
   - **신청형 관리 리서치(Managed / recruited research)** — 유저가 "참여 신청" → 리서처가 백오피스에서 **스크리닝 → 대상자 선정 → 일정/세션 진행 → 정산**. (인터뷰·일기조사·UT·장기 패널·고단가 전문가 조사 등)
4. **AI는 인지부담 절감 레이어다.** 설계(문항 생성/로직 추천), 검수(유도·모순·민감문항 탐지), 표본(쿼터·필요표본 추천), 분석(자동 인사이트·유의차 탐지)까지 전 단계에 보조로 깔되, 결정권은 리서처에게 둔다.
5. **단계적 구축**: Phase 0(분리·정리) → 1(유저 앱 독립) → 2(백오피스 프로젝트 관리) → 3(신청·스크리닝·선정) → 4(관리 리서치 운영·일정) → 5(AI 심화·품질·정산).

## 1. 시장 지형과 분류 체계

리서치 산업은 단일 시장이 아니라 역할이 다른 네 개 계층이 사슬로 엮여 있다. 잇츠미가 어디를 노리는지 명확히 하려면 이 지형도가 먼저 필요하다.

| 계층                           | 정의                                  | 대표 기업                                                         | 핵심 자산                         | 잇츠미 관련도                    |
| ------------------------------ | ------------------------------------- | ----------------------------------------------------------------- | --------------------------------- | -------------------------------- |
| **풀서비스 리서치펌**          | 기획~분석~컨설팅까지 대행             | Kantar, Ipsos, NielsenIQ, GfK                                     | 방법론·인력·산업 패널             | ◐ (관리 리서치의 운영 모델 참고) |
| **샘플/패널 공급자(Exchange)** | 응답자 모수를 API/마켓플레이스로 공급 | Dynata, Cint, Lucid                                               | 1st-party 패널, 프로그래매틱 매칭 | ● (잇츠미 패널 = 핵심 자산)      |
| **DIY/셀프서브 플랫폼**        | 연구자가 직접 설계·필딩               | Qualtrics, SurveyMonkey/Momentive, Toluna Start, Attest, Pollfish | 빌더·자동화·대시보드              | ● (백오피스 청사진)              |
| **질적/리크루팅 플랫폼**       | 인터뷰·UT 대상자 모집·스크리닝·스케줄 | User Interviews, Respondent, dscout, UserTesting                  | 리크루팅·스크리너·인센티브·캘린더 | ● (신청형 관리 리서치)           |
| **모바일 보상형 패널(국내)**   | 모바일 앱 기반 리워드 설문            | 오픈서베이, 패널나우, 틸리언                                      | 모바일 패널·즉시보상·DIY          | ★ (잇츠미 직접 경쟁/모델)        |

> **잇츠미의 좌표**: "모바일 보상형 패널(★) + DIY 셀프서브(●) + 질적 리크루팅(●)" 의 결합. 즉 **오픈서베이의 패널·보상 모델 + Qualtrics식 빌더/대시보드 + User Interviews식 신청·스크리닝**을, 게이미피케이션(정령 육성)으로 리텐션을 묶은 형태.

## 2. 기업별 심층 분석

각 기업은 ① 개요·포지션 ② 서비스 라인 ③ **리서처(백오피스) 워크플로우** ④ **응답자(패널) 경험·보상** ⑤ 표본·스크리닝·리크루팅 ⑥ 품질관리 ⑦ AI ⑧ 분석·산출물 ⑨ 가격모델 ⑩ **잇츠미 시사점** 순으로 해부한다.

### 2.1 Kantar

**① 개요·포지션** — 세계 최대급 마케팅 데이터·컨설팅 그룹. 브랜드·미디어·소비자 패널을 아우르는 풀서비스 + 점진적 플랫폼(자동화 솔루션)화.

**② 서비스 라인** — Brand 추적(BrandZ/브랜드 가이던스), 광고 사전·사후 테스트(LINK+), Worldpanel(구매 패널), Profiles(샘플/패널 네트워크), Marketplace(자동화 DIY 솔루션 묶음), Media(시청률·믹스).

**③ 리서처 워크플로우** — 전통적으로 컨설턴트 대행 중심이나, **Kantar Marketplace**에서 표준화된 솔루션(컨셉 테스트, 광고 테스트, 브랜드 리프트)을 템플릿화 → 설정→필딩→자동 리포트의 셀프서브 경로 제공. 정규화된 **벤치마크 DB**(수만 건의 과거 결과)와 비교해 점수의 의미를 해석해주는 것이 강점.

**④ 응답자 경험·보상** — 자체+파트너 패널. 보상은 포인트/현금/추첨. 소비자 입장에서는 "조사 참여" 경험이 무겁고 게이미피케이션 약함.

**⑤ 표본·스크리닝** — 인구통계·행동 쿼터, 산업별 전문 패널(의료·B2B), 글로벌 100+개국 표본.

**⑥ 품질관리** — 디지털 핑거프린팅, 응답속도/스트레이트라이닝 탐지, 트랩 문항, 패널 검증(중복·봇).

**⑦ AI** — 광고/컨셉 테스트의 결과 자동 해석, 크리에이티브 AI 예측(사전 평가), 텍스트 코딩 자동화.

**⑧ 산출물** — 정규화 점수 + 벤치마크 비교 + 권고. PPT/대시보드.

**⑨ 가격** — 솔루션·표본 규모별. 고가·B2B 계약 중심.

**⑩ 잇츠미 시사점** — **벤치마크 DB의 힘**. 단순 결과가 아니라 "업종 평균 대비 어떤지"를 보여줄 때 가치가 폭발. 잇츠미도 누적 응답으로 **카테고리 벤치마크**(예: "20대 커피 선호 평균")를 만들어 리서처 리포트에 비교선으로 제공하면 차별화. 또한 **솔루션 템플릿화**(컨셉 테스트/만족도/NPS 등 사전 설계된 패키지)는 인지부담 절감의 정석.

### 2.2 Ipsos

**① 개요·포지션** — 풀서비스 글로벌펌이지만 **Ipsos.Digital**로 자동화 셀프서브를 가장 공격적으로 밀어붙인 곳.

**② 서비스 라인** — 시장이해·브랜드헬스·광고테스트·UX·여론조사. **KnowledgePanel**(확률표집 기반 모집단 대표성 패널 — 비확률 온라인 패널과 차별), **Ipsos.Digital**(FastFacts 빠른 설문, ProductTesting, 컨셉/광고 테스트의 DIY 자동화).

**③ 리서처 워크플로우** — Ipsos.Digital: 템플릿 선택 → 문항 자동 구성 → 표본·쿼터 설정 → 견적 실시간 산출 → 발주 → 며칠 내 자동 리포트. "전문가가 만든 설계를 셀프로"가 핵심.

**④ 응답자 경험·보상** — i-Say 등 패널, 포인트→상품/기프트카드. KnowledgePanel은 모집 단계에서 오프라인 확률표집(대표성 우선).

**⑤ 표본·스크리닝** — 확률/비확률 패널 병행, 강력한 쿼터 엔진, 가중치(weighting) 처리.

**⑥ 품질관리** — Ipsos만의 품질 프로토콜(중복·부정·속도·일관성), 패널 위생 관리.

**⑦ AI** — 설문 자동 생성, 오픈엔드 자동 코딩, 결과 내러티브 생성.

**⑧ 산출물** — 자동 대시보드 + 권고, 가중·유의차 처리된 표.

**⑨ 가격** — FastFacts류는 문항·표본 단위 종량제(저가 진입) + 대형은 프로젝트 계약.

**⑩ 잇츠미 시사점** — **실시간 견적 + 종량제 진입**(문항 수 × 표본 수 → 포인트 예산 자동 산출)을 백오피스에 그대로 이식할 가치가 큼. 또한 **대표성/가중치** 개념은 즉시참여형의 자기선택 편향을 보정하는 신뢰 장치 — 잇츠미 리포트에 "표본 구성 vs 모집단" 비교와 사후 가중 옵션을 넣으면 B2B 신뢰도가 올라간다.

### 2.3 NielsenIQ (& Nielsen)

**① 개요·포지션** — 소비자/리테일 측정(NielsenIQ)과 미디어 시청측정(Nielsen)의 측정(measurement) 강자. 설문보다 **행동·거래 데이터(passive)** 가 본질.

**② 서비스 라인** — 소매 스캔·소비자 패널(구매 기록), 미디어 오디언스, BASES(신제품 성공 예측).

**③ 리서처 워크플로우** — 측정 데이터 구독 + 분석 컨설팅. 설문은 보조.

**④ 응답자 경험·보상** — 홈스캔류 패널(구매 영수증/스캐너 제출 → 포인트·추첨). 장기 지속 패널 = **습관적 데이터 제공**이 핵심.

**⑤ 표본·스크리닝** — 대표성 있는 가구 패널 구성, 장기 유지·이탈관리.

**⑥ 품질관리** — 데이터 검증·결측 보정.

**⑦ AI** — BASES의 신제품 매출 예측 모델.

**⑧ 산출물** — 시장점유·트렌드·예측.

**⑨ 가격** — 고가 구독.

**⑩ 잇츠미 시사점** — **수동적·지속적 데이터 제공(passive metering)** 과 **장기 패널 리텐션**. 잇츠미의 정령 육성/스트릭은 이 "습관화"를 게임으로 푸는 장치다. 향후 영수증/구매 인증·라이프로깅 같은 **수동 데이터 적립**을 정령 성장과 묶으면 차별적 데이터 자산이 된다. 또한 "내 데이터가 자산으로 쌓인다"는 NielsenIQ 패널 철학을 유저에게 **데이터 허브**로 시각화.

### 2.4 Dynata

**① 개요·포지션** — 세계 최대급 **1st-party 데이터/샘플 공급자**. 연구자에게 "응답자"를 공급하는 인프라.

**② 서비스 라인** — 프로그래매틱 샘플(API), 패널 매칭, 일부 셀프서브.

**③ 리서처 워크플로우** — 외부 설문 도구에 표본을 연결(라우팅). 타깃·쿼터·인센티브를 설정하면 패널 라우터가 적격 응답자를 실시간 배분.

**④ 응답자 경험·보상** — 다수 제휴 패널·앱을 통한 보상(포인트/현금/마일리지). 응답자는 여러 설문을 순환.

**⑤ 표본·스크리닝 (핵심)** — **라우팅/스크리닝 엔진**: 응답자가 들어오면 스크리너로 적격 여부 판정 → 적합한 설문으로 라우팅, 쿼터 충족 시 자동 종료(quota full), 부적격은 다른 설문으로 재라우팅. 인센티브는 실제 소요시간(LOI)·난이도 기반.

**⑥ 품질관리** — 디지털 핑거프린팅, 부정·중복·봇 차단, 응답 패턴 이상 탐지가 사업의 생명선.

**⑦ AI** — 표본 가용성/타깃 도달 예측.

**⑧ 산출물** — 응답 데이터 자체(분석은 연구자 몫).

**⑨ 가격** — CPI(Cost Per Interview): 타깃 희소성·LOI·인시던스율(IR)로 단가 결정.

**⑩ 잇츠미 시사점** — **라우팅·쿼터·CPI 모델이 잇츠미 매칭 엔진의 교과서**. 유저가 피드를 열면 프로필·관심사·과거응답 기반으로 **적격 설문만 노출**하고, 쿼터가 차면 피드에서 내리고, 보상은 LOI×난이도로 산정. CPI 개념을 "포인트 단가 = 예상 소요시간 × 타깃 희소도 × 난이도"로 백오피스 견적에 반영.

### 2.5 Qualtrics

**① 개요·포지션** — 경험관리(XM) 플랫폼의 대표. **설문 빌더·로직·분석의 사실상 표준**. (B2B SaaS, 패널은 파트너로 조달)

**② 서비스 라인** — Survey/Research Core, CustomerXM·EmployeeXM·BrandXM, Stats iQ(자동 통계), Text iQ(텍스트 분석), XM Discover, Qualtrics Audiences/파트너 패널.

**③ 리서처 워크플로우 (정수)** —

- **블록·로직**: 질문 블록, 분기(branch), 디스플레이 로직, 스킵 로직, 랜덤화, 쿼터.
- **문항 타입 풍부**: 단일/복수/매트릭스/슬라이더/순위/NPS/히트맵/사이드바이사이드/맥스디프(MaxDiff)/컨조인트(Conjoint).
- **파이핑(piping)**: 앞 답변을 뒤 문항에 삽입(개인화).
- **임베디드 데이터·메타**: URL 파라미터·패널 속성 주입.
- **테마·다국어**: 브랜딩 테마, 번역 매트릭스.
- **배포 채널**: 익명 링크, 이메일, QR, SMS, 임베드, 오프라인 앱.
- **워크플로우 자동화**: 응답 트리거 → 알림/티켓/웹훅.

**④ 응답자 경험** — 반응형 설문, 모바일 최적화, 진행률 표시. (자체 보상 패널 아님)

**⑤ 표본** — 파트너 패널(Audiences)로 조달, 쿼터·할당.

**⑥ 품질관리** — RelevantID(중복·부정), 봇 탐지(reCAPTCHA), 속도/직선응답 플래그, 주의확인(attention check) 문항.

**⑦ AI** — 설문 문항 추천, Text iQ 감성·토픽 자동분류, Stats iQ 자동 유의차·드라이버 분석, 최근 생성형 요약.

**⑧ 산출물** — 실시간 리포트·대시보드·크로스탭·드라이버 분석·내보내기(CSV/SPSS).

**⑨ 가격** — 좌석/응답 기반 엔터프라이즈 구독.

**⑩ 잇츠미 시사점** — **백오피스 빌더의 기능 로드맵 = Qualtrics 축소판**. 우선순위: (1) 분기·스킵·디스플레이 로직, (2) 쿼터, (3) 파이핑/개인화, (4) 랜덤화, (5) 고급 문항(NPS·매트릭스·순위·MaxDiff). **단, 잇츠미의 철학은 "Qualtrics의 복잡함을 AI로 감춘다"** — 로직을 직접 그리는 대신 "이 답을 고른 사람만 다음 질문" 같은 자연어 규칙 → AI가 분기 구성. Stats iQ식 **자동 인사이트**(유의차·드라이버)는 인사이트 페이지의 핵심 차별점.

### 2.6 오픈서베이 (OpenSurvey) — 집중 분석 (가장 가까운 모델)

**① 개요·포지션** — 국내 모바일 리서치 1세대. **모바일 패널 기반 DIY 셀프서브 + 대행**의 결합. "빠르고 저렴하게, 모바일에서" 가 핵심 메시지.

**② 서비스 라인** —

- **DIY 셀프서브 설문**: 웹 콘솔에서 직접 설계·발송·결과 확인.
- **패널 조사(오베이/오픈서베이 패널)**: 자체 모바일 패널에 즉시 발송 → 수 시간~수일 내 수집.
- **솔루션 템플릿**: 만족도(NPS/CSAT), 브랜드 인지, 컨셉 테스트, U&A 등 사전 설계 패키지.
- **데이터 트렌드 리포트**(콘텐츠 마케팅): 무료 트렌드 리포트로 리드 확보.

**③ 리서처 워크플로우** — 템플릿 선택 또는 백지 설계 → 문항 편집(보기·로직·이미지) → 타깃(성·연령·지역·쿼터) 설정 → **실시간 견적·예상 수집기간 표시** → 발송 → 실시간 응답 현황/크로스탭/리포트 자동 생성 → 다운로드. **속도와 단순함**이 셀링포인트.

**④ 응답자 경험·보상 (벤치마크 핵심)** —

- 모바일 앱에서 **설문 푸시 → 짧은 설문 → 즉시 포인트** 적립.
- 포인트 → 현금/기프티콘 교환(출금 임계값 존재).
- 응답자는 "틈새시간에 용돈벌이" 동기. **이탈 방지**가 과제(잇츠미는 정령 육성으로 차별).

**⑤ 표본·스크리닝** — 패널 프로필(성·연령·지역·직업·관심사) 기반 타깃팅, 쿼터. 스크리닝 문항으로 적격자 선별 후 본설문.

**⑥ 품질관리** — 불성실 응답(속도·직선) 필터, 중복·부정 차단, 패널 신뢰도 관리.

**⑦ AI** — 문항 추천·오픈엔드 분석 등 점진 도입.

**⑧ 산출물** — 실시간 대시보드, 크로스탭(교차분석), 워드클라우드, 리포트 자동화, 엑셀/PPT.

**⑨ 가격** — **문항 수 × 응답 수 × 타깃 난이도** 종량제(저가 진입) + 대행 프로젝트.

**⑩ 잇츠미 시사점** — **잇츠미 = "오픈서베이 + 게이미피케이션 + 신청형 질적 리서치"** 로 포지셔닝하면 가장 자연스럽다. 차용할 것:

- 백오피스: 템플릿 솔루션, 실시간 견적·수집기간 예측, 크로스탭·자동 리포트.
- 유저 앱: 푸시→짧은 설문→즉시 보상, 포인트 교환·출금 임계값.
- 잇츠미만의 우위: 정령 육성/스트릭(리텐션), 신청형 관리 리서치(질적), 데이터 허브(데이터 자산 시각화).

## 4. 리서치펌이 실제로 하는 "모든 것" — 업무 전 과정 해부

상위 업체가 대행/플랫폼으로 제공하는 전체 파이프라인. 잇츠미 백오피스가 장기적으로 커버해야 할 기능의 마스터 체크리스트다.

### 4.1 기획(Define)

- 리서치 목표·가설·의사결정 질문(decision question) 정의
- 조사 방법 선택(정량 vs 정성, 횡단 vs 추적)
- 핵심 지표(KPI)·분석 계획 사전 수립
- **잇츠미 적용**: AI가 "무엇을 알고 싶은가?" 한 줄 입력 → 목표·가설·추천 문항·방법 초안 생성.

### 4.2 설계(Design)

- 설문 구조: 도입·스크리너·본문·인구통계·종료
- 문항 작성·보기 설계·척도 선택(리커트/NPS/MaxDiff/컨조인트)
- 로직: 분기·스킵·파이핑·랜덤화·쿼터
- 편향 제거: 유도·이중·모순·민감 문항 점검, 보기 순서 효과
- 다국어·접근성
- **잇츠미 적용**: AI 문항 생성 + AI 검수(유도/모순/민감/길이) + 모바일 프리뷰 + 자연어 로직.

### 4.3 표본 설계(Sampling)

- 모집단 정의·표본틀·표본크기 산정(신뢰수준·오차범위)
- 쿼터(성·연령·지역…)·가중치 설계
- 인시던스율(IR)·예상 LOI·도달 가능성 추정
- **잇츠미 적용**: 필요표본 계산기, 쿼터 빌더, 패널 가용성 실시간 추정, CPI식 포인트 예산 자동 산정.

### 4.4 모집·스크리닝(Recruit & Screen)

- 패널 라우팅·초대·할당
- 스크리너로 적격 판정·쿼터 충족 관리·quota full 처리
- (질적) 후보 풀 구성 → 수동/자동 선별 → 일정 예약
- **잇츠미 적용**: 즉시참여는 자동 라우팅, 신청형은 스크리너→후보 리스트→리서처 선정→통보→캘린더.

### 4.5 필딩(Field)

- 배포·실시간 수집 모니터링(유입·완료·중도이탈·속도)
- 쿼터 추적, 리마인더 발송, 현장 이슈 대응
- **잇츠미 적용**: 실시간 대시보드, 쿼터 게이지, 푸시 리마인더(스트릭/정령 연계), 자동 종료.

### 4.6 품질관리(Quality)

- 스피딩·스트레이트라이닝·트랩/주의확인·논리모순·중복·봇·핑거프린팅
- 부정 응답 제거·재수집, 패널 신뢰도 점수
- **잇츠미 적용**: 어뷰징 엔진(경고→쿨다운→밴) + 신뢰도 점수 + 자동 클린/재필딩.

### 4.7 집계·분석(Analyze)

- 데이터 클리닝·코딩(오픈엔드)·가중·크로스탭(교차분석)
- 유의차 검정·드라이버 분석·세그먼트·텍스트/감성 분석
- **잇츠미 적용**: 크로스탭, 자동 유의차/드라이버(Stats iQ식), 오픈엔드 AI 코딩·워드클라우드.

### 4.8 리포팅(Report)

- 대시보드·인포그래픽·내러티브·권고·벤치마크 비교
- 내보내기(CSV/SPSS/PPT/PDF)·공유·권한
- **잇츠미 적용**: 자동 인사이트 요약(생성형), 카테고리 벤치마크선, CSV/PDF, 공유 링크.

### 4.9 정산·운영(Operate)

- 응답자 인센티브 지급(포인트→현금/기프티콘), 세금/정산
- 프로젝트 청구·구독·재배포, 협업·권한·감사로그
- **잇츠미 적용**: 지갑·교환·출금 임계값, 포인트 예산 차감·정산, 팀 권한, 감사로그.

## 5. 잇츠미 적용 설계 — 두 개의 분리된 서비스

### 5.1 완전 분리 아키텍처 (가장 중요)

> **원칙: 백오피스와 유저 앱은 진입점·인증·코드·디자인·배포가 모두 분리된 별개 제품이다.**

| 구분               | 백오피스 (리서처 콘솔)             | 유저 앱 (응답자)               |
| ------------------ | ---------------------------------- | ------------------------------ |
| 사용자             | 리서처·마케터·PM·관리자            | 일반 패널(응답자)              |
| 주 디바이스        | PC(웹)                             | 모바일(앱/PWA), PC도 응답 가능 |
| 진입 도메인(예)    | `studio.itsme.app` / `/researcher` | `app.itsme.app` / `/` (기본)   |
| 인증               | 이메일/조직 SSO·팀 초대            | 카카오/애플/구글 소셜 1탭      |
| 디자인 철학        | 정보 밀도·생산성·AI 보조           | 단순·몰입·보상·게임화          |
| 코드 진입 컴포넌트 | `ResearcherApp` (워크스페이스)     | `PanelistApp` (독립 앱)        |
| 빌드 산출물(장기)  | 별도 라우트/번들 분리              | 별도 라우트/번들 분리          |

**현재 구조 → 목표 구조**

```
[AS-IS] 단일 App.tsx
  └─ topbar(역할 토글: 리서처 ↔ 응답하기)
     ├─ ResearcherWorkspace (항상)
     └─ PanelistApp (모달 오버레이)   ← "흰 박스"의 원인

[TO-BE] 경로/도메인 기반 분리
  / (기본)            → PanelistApp        (응답자 = 메인 서비스)
  /researcher 또는
  studio.itsme.app    → ResearcherApp      (백오피스 콘솔, 독립)
  ※ 역할 토글·응답 모달·"응답 체험" 버튼 전부 제거
  ※ 개발 편의용 미리보기가 필요하면 콘솔 안의 "모바일 프리뷰"로만 제공(설계 검증용),
     실제 응답 서비스와는 분리
```

**즉시 조치 (Phase 0)**

1. App.tsx의 `topbar__role` 토글, `응답 체험` 버튼, `responderOpen` 모달 제거 → "흰 박스" 소멸.
2. 경로 기반 진입 도입(가벼운 `window.location.pathname` 분기 또는 추후 라우터): `/researcher`면 `ResearcherApp`, 그 외 `PanelistApp`.
3. 리서처 콘솔 상단바는 콘솔 전용(브랜드+프로젝트+팀+계정), 유저 앱 상단바는 앱 전용(포인트·정령). 공유 topbar 폐기.

### 5.2 백오피스(리서처 콘솔) 청사진

**정보구조 (좌측 내비 = 프로젝트 중심)**

```
홈/대시보드     — KPI, 진행 중 프로젝트, 할 일, 빠른 시작
프로젝트        — 리서치 단위(설문형 / 관리형) 리스트·칸반·상태
  └ 프로젝트 상세
     ├ 개요(목표·방법·표본·일정·예산)
     ├ 설계(설문 빌더 / 스크리너 빌더)
     ├ 표본·타깃(쿼터·필요표본·견적)
     ├ 모집·스크리닝(후보·선정 — 관리형)
     ├ 필딩(실시간 모니터링·쿼터·리마인더)
     ├ 품질(어뷰징·신뢰도·클린)
     ├ 분석(크로스탭·자동 인사이트·벤치마크)
     └ 리포트/내보내기
설계 스튜디오   — 빌더(독립 진입, AI 생성·검수)
패널/오디언스   — 모집단 규모·세그먼트·가용성
인사이트        — 결과·대시보드·내보내기
지갑/정산       — 포인트 예산·차감·청구
팀/설정         — 권한·감사로그·브랜딩
```

**철학: "심플·직관 + AI 인지부담 절감"**

- 모든 복잡 기능에 **AI 디폴트 + 수동 오버라이드**. (예: 자연어로 "20대 여성 200명, 커피 브랜드 인지도" → 목표·문항·쿼터·견적 초안 자동 구성)
- **솔루션 템플릿**(NPS/CSAT/컨셉테스트/U&A) 으로 백지 공포 제거.
- **3단 빌더**(문항 리스트 / 편집 / 모바일 프리뷰) 유지·강화.
- **점진적 공개(progressive disclosure)**: 고급 로직·가중치는 접어두고 필요할 때만.

### 5.3 유저 앱(응답자) 청사진

**정보구조 (하단 탭 = 4개)**

```
홈(탐색)   — ① 즉시참여 설문 덱(스와이프)  ② 추천/제안된 리서치  ③ 신청 가능한 관리형 리서치
참여(투두) — 내가 신청/선정된 리서치, 일정·마감·다회차 미션을 todo·캘린더로
정령(성장) — 데이터 허브·정령 육성·스트릭·진화·내 데이터 자산 시각화
상점/지갑  — 포인트·교환·출금·내역
```

**두 가지 리서치 유형의 유저 경험**

1. **즉시참여형 설문 (현재 구현)**

- 피드에서 적격 설문만 노출(라우팅) → 스와이프/탭 응답 → 즉시 포인트 → 정령 성장.
- LOI×난이도 기반 포인트 표기, 쿼터 차면 자동 비노출.

2. **신청형 관리 리서치 (신규)**

- 카드: "심층 인터뷰 60분 / 5만 P / 다음 주 / 모집 30명" 형태로 노출.
- **[참여 신청]** → **스크리너 설문** 응답 → "검토 중" 상태.
- 리서처가 백오피스에서 후보 풀에서 **선정** → 유저에게 **선정/미선정 통보**(푸시).
- 선정 시 **일정 예약**(가능 시간 선택 → 캘린더 확정), 사전 안내·준비물.
- 세션 진행(인터뷰/UT/일기 다회차 미션) → 완료 확인 → **인센티브 지급**.
- **참여 탭의 todo/캘린더**: 신청 현황, 예정 세션, 다회차 미션 마감, 리마인더를 직관적으로.

### 5.4 신청→스크리닝→선정→진행→정산 라이프사이클 (상태기계)

```
[유저측 상태]
applied(신청) → screening(스크리너 제출) → review(검토중)
  → selected(선정) | rejected(미선정)
  → scheduled(일정확정) → in_session(진행) → completed(완료) → paid(지급)
  (waitlist/대기, no_show/노쇼, canceled/취소 분기 포함)

[리서처측 액션]
모집 공개 → 후보 리스트(스크리너 응답·프로필 보기)
  → 필터/정렬(쿼터 충족 위해) → 선정/대기/거절
  → 일정 조율 → 세션 관리 → 완료 승인 → 인센티브 정산
```

**데이터 모델 추가 제안 (개념)**

- `Project` { id, type: 'survey'|'managed', goal, method, status, quota, budget, timeline }
- `ScreenerResponse` { projectId, pid, answers, score }
- `Application` { id, projectId, pid, status(위 상태기계), scheduledAt, sessionType, payout }
- `Session` { applicationId, kind: 'interview'|'ut'|'diary', schedule, deliverables, completionState }
- `Incentive` { applicationId, amount, status: 'pending'|'paid' }
- 기존 `Survey/Response/Wallet/Pet` 와 연결.

### 5.5 AI 인지부담 절감 설계 (백오피스 전 단계)

| 단계     | AI 보조                                     | 사람 결정 |
| -------- | ------------------------------------------- | --------- |
| 기획     | 목표 한 줄 → 가설·방법·KPI 초안             | 채택/수정 |
| 설계     | 문항·보기·척도 생성, 자연어→로직            | 편집      |
| 검수     | 유도·이중·모순·민감·길이 탐지 + 수정안      | 반영      |
| 표본     | 필요표본·쿼터·견적·LOI 추정                 | 승인      |
| 스크리닝 | 후보 적격 점수·추천 선정                    | 최종 선정 |
| 분석     | 유의차·드라이버·세그먼트·오픈엔드 코딩·요약 | 해석      |
| 리포트   | 내러티브·벤치마크 비교 자동 작성            | 검수      |

원칙: **AI는 초안과 신호를, 리서처는 결정을.** 신뢰를 위해 항상 "왜 이렇게 제안했는지" 근거 표기.

### 5.6 품질·정산

- 어뷰징 엔진(속도·직선·트랩·중복·핑거프린팅) → 경고/쿨다운/밴 + 신뢰도 점수.
- 즉시참여: 자동 보상, 부정 시 회수.
- 관리형: 완료 승인 후 지급, 노쇼 패널티.
- 지갑: 포인트 예산 차감(리서처) ↔ 적립·교환·출금(유저), 출금 임계값·기프티콘 연동.

## 7. 현재 코드 갭 분석 & 즉시 조치(Phase 0 상세)

| 항목          | 현재                        | 문제                  | 조치                             |
| ------------- | --------------------------- | --------------------- | -------------------------------- |
| 진입 구조     | 단일 App + 역할 토글        | 백/유저 혼재          | 경로 분기(`/researcher` vs `/`)  |
| 응답 미리보기 | `PanelistApp` 모달 오버레이 | "흰 박스"·서비스 혼동 | 모달 제거, 유저 앱은 독립 라우트 |
| 공유 topbar   | 브랜드+역할+헬스 공유       | 두 제품이 같은 헤더   | 콘솔/앱 각자 헤더                |
| 설문 단위     | `Survey` 중심               | 프로젝트·관리형 부재  | `Project` 도입(Phase 2)          |
| 신청·스크리닝 | 없음                        | 질적 리서치 불가      | 상태기계 도입(Phase 4)           |
| 참여 일정     | 없음                        | 유저 todo/캘린더 부재 | 참여 탭(Phase 1/4)               |

> **Phase 0는 코드 변경량이 작고 위험이 낮음** — 토글/모달/공유 헤더 제거 + 경로 분기. 이 문서 확정 후 바로 착수 가능.

## 8. 부록

### 8.1 용어

- **LOI** Length of Interview(예상 소요시간) · **IR** Incidence Rate(적격률) · **CPI** Cost Per Interview · **Quota** 표본 할당 · **Screener** 적격 선별 설문 · **Routing** 적격 설문으로 응답자 배분 · **Weighting** 가중 · **Straightlining** 직선응답 · **Speeding** 초고속 불성실 응답.

### 8.2 KPI

- 유저(B2C): 가입→첫완료 전환, D1/D7 리텐션, 일일 완료수, 스트릭 유지율, 교환 전환율, 신청→선정→완료 전환.
- 리서처(B2B): 설계 소요시간, 목표표본 달성시간, 유효응답률, 견적→발주 전환, 재배포율, 대시보드 활성률.

### 8.3 리스크

1. 두 서비스 분리 비용(인증·도메인·번들) 관리.
2. 즉시참여 자기선택 편향 → 가중·대표성 장치로 보완.
3. 관리형 리서치 운영 복잡도(일정·노쇼·정산) → 상태기계·자동화로 통제.
4. 보상 비용 구조 안정성, 어뷰징 오탐.
5. 개인정보·PID 보안.
