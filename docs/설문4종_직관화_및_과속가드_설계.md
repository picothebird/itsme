# 설문 4종 직관화 + 과속응답 가드 UX 설계

> 선행 문서: [`글래스모피즘_토큰_및_모바일적용_설계.md`](./글래스모피즘_토큰_및_모바일적용_설계.md)
> 대상 코드: `apps/frontend/src/features/PanelistMobile.tsx`(`ResponseQuestion`, `LikertScale`),
> `apps/frontend/src/App.css`, 어뷰징 규칙 `apps/backend/src/domain/abuse.ts`

목표: **학습 없이도(zero-learning) 탁탁 누르는** 설문 경험 + **너무 빠른 응답 경고**를
최신 글래스 디자인에 맞게 개편.

---

## 1. 현재 4종 설문 타입 진단

| 타입     | 코드값   | 현재 UI                                    | 직관성 이슈                               |
| -------- | -------- | ------------------------------------------ | ----------------------------------------- |
| 단일선택 | `single` | 세로 보기 버튼, 탭 즉시 220ms 후 자동 다음 | 양호. 선택 피드백 약함                    |
| 복수선택 | `multi`  | 체크형 버튼 + 하단 "다음" CTA              | "모두 선택" 안내가 작아 1개만 고르고 멈춤 |
| 리커트   | `likert` | 표정 아이콘 5점 + 양끝 라벨                | 점-라벨 매핑이 한눈에 안 들어옴           |
| 자유응답 | `text`   | textarea + "다음"                          | 분량 감 없음. 빈 응답 방지만              |

핵심 처리(`ResponseQuestion`):

- `single`/`likert`: 탭 → 220ms 뒤 `onAnswer([id])` 자동 진행.
- `multi`/`text`: 하단 CTA로 확정.
- `latencyMs = max(300, now - startedAt)`를 서버로 전송, 서버가 사후 판정.

## 2. 직관화 원칙 (Zero-learning)

1. **타입별 "행동 힌트"를 한 줄로 명확히.** (단일=하나만, 복수=여러개 OK+다음, 리커트=정도, 자유=직접)
2. **선택 즉시 강한 피드백.** 글래스 카드가 컬러 틴트로 차오르고, 체크가 팝(이미 `pm-bullet-pop`).
3. **복수선택 진행 유도.** 1개 이상 고르면 CTA가 "다음 · N개"로 활성·강조(이미 존재) +
   카드 우상단에 선택 순번/체크를 더 또렷하게.
4. **리커트 가독.** 점마다 표정 + 선택 시 가운데에 현재 라벨 크게(이미 `pm-likert__current`).
   글래스 알약 + 선택 컬러 틴트로 "지금 어디" 명확.
5. **자유응답 분량감.** 글자 수 카운터(`n/500`)와 부드러운 최소 권장 안내.
6. **진행감.** 상단 `n / total` + 상단 진행바(기존 topbar progress) 유지.

> 변경은 **API·데이터 구조 무변경**(클래스/문구/소량 상태만). 흐름 로직 보존.

## 3. 과속응답(Speeding) 가드 — 사전 예방형으로

### 3.1 기존 동작 (사후)

서버 `isSpeeding`: `latencyMs < minDwellMs(questionTextLength)`.
`minDwellMs = max(800ms, 글자수/16자초 ×1000)`. 누적 strike 3회 → 차단.
프런트는 응답 **후** `outcome.abuse.level === 'warn'`일 때만 토스트.
→ 문제: 이미 빠르게 눌러 strike가 쌓인 뒤에야 안다. 사용자에겐 갑작스럽고 불친절.

### 3.2 기획 의도 (벤치마크 문서)

`docs/리서치플랫폼_벤치마크_분석_및_적용설계.md`:

> "어뷰징 엔진(경고→쿨다운→밴) + 신뢰도 점수"
> "불성실 응답(속도·직선) 필터"

즉 **점진적 개입**: 1차 부드러운 경고 → 반복 시 제재. 프런트는 1차 경고를 **선제적으로** 담당.

### 3.3 새 동작 (사전 가드, 클라이언트)

문항이 바뀌면 `startedAt` 기록(기존). 클라이언트에 **가벼운 최소 숙독시간**을 둔다.

```
clientMinDwellMs = clamp(450ms, 글자수 × 22ms, 1600ms)
```

- 서버 기준(`/16자초`≈62.5ms/자, floor 800ms)보다 **느슨하게** 잡아 정상 사용자를 막지 않는다.
  목적은 "차단"이 아니라 "0.x초 만에 반사적으로 누른" 케이스에 한 번 숨 고르게 하는 것.
- 동작:
  - `single`/`likert` 탭 또는 `multi`/`text` CTA를 `clientMinDwellMs` 이전에 누르면
    → `onAnswer`를 막지 않고 **인라인 미세경고**를 띄운다(파괴적 차단 X).
    "문항을 충분히 읽어 주세요 🙂" + 진행은 1.2초 뒤 자동 또는 한 번 더 누르면 진행.
  - 정상 시간 이후엔 평소처럼 즉시 진행.
- 서버 사후 판정은 그대로 둔다(이중 안전망). 클라 경고는 신뢰도 보호용 UX.

### 3.4 인터랙션 상세

- 경고 표현은 **글래스 토스트**(`.pm-toast--guard`)로 비파괴적·짧게.
- 같은 문항에서 1회만 경고(중복 방지 플래그). 두 번째 탭부터는 그대로 진행.
- 모션 민감/접근성: 경고는 텍스트+아이콘, 흔들림 애니메이션 없음.

## 4. 컴포넌트 변경 요약

| 과속 사전 가드               | `clientMinDwellMs` + 인라인 경고 | `PanelistMobile.tsx ResponseQuestion` |

**비변경(안전):** 설문 데이터 모델, `api.submitAnswer` 시그니처, 단계 전환 로직,
서버 어뷰징 규칙(`abuse.ts`).
