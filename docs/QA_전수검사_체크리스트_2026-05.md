## 0. 사용 규칙 (검사 수행자/AI 에이전트용)

1. **한 번에 하나의 화면(섹션)** 만 in-progress로 잡고, 그 안의 모든 체크박스를 끝낸 뒤 다음 섹션으로 이동한다.
2. 각 체크 항목은 4개 렌즈 태그로 분류한다 — 발견 즉시 결함은 `🐞결함`, 개선여지는 `✨개선`으로 표시하고 하단 **이슈 로그**에 적는다.
3. **재현 절차가 없는 체크는 무효**다. 각 화면 상단의 _가짜 데이터 준비_ 절차를 먼저 수행해 동일 상태를 만든 뒤 검사한다.
4. 검사 한 사이클이 끝나면 `npm run lint/typecheck/build --workspace=frontend`, (백엔드 변경 시) `npm test --workspace=backend` 가 모두 green 인지 확인한다.
5. 체크박스 의미: `[ ]` 미검사 · `[~]` 검사 중/부분 · `[x]` 통과(이슈 없음 또는 이슈 등록 후 수정 완료).

### 검사 4렌즈 (각 항목에 최소 1개 이상 적용)

| 태그  | 렌즈              | 핵심 질문                                                                               |
| ----- | ----------------- | --------------------------------------------------------------------------------------- |
| **T** | Technical(기능)   | 클릭/입력/API가 의도대로 동작하나? 상태 전이·에러 처리·중복 방지가 정확한가?            |
| **U** | Cognition(인지)   | 유저가 _다음에 뭘 해야 할지_ 즉시 아는가? 라벨·위계·피드백·빈상태 카피가 명확한가?      |
| **A** | Animation(모션)   | 터치/전이에 _과하지 않고 의미 있는_ 모션이 붙나? 60fps·reduced-motion 대응·끊김 없는가? |
| **D** | Data/Edge(데이터) | 0건/최대치/실패/오프라인/권한/경계값에서 깨지지 않나? 토큰·폰트·반응형 일관성은?        |

## 1. 가짜 데이터 · 시드 / 시나리오 준비 (전 검사 공통 선행)

> 백엔드는 **인메모리 저장소**라 서버 재시작 또는 `/dev/reset` 으로 초기화된다. 모든 시나리오는 reset 직후 기준으로 기술한다.

### 1.1 환경 기동

- [ ] **S-1 (T)** 백엔드 기동: 헬스 `GET http://localhost:4000/health` → `{ status: 'ok' }` 확인.
- [ ] **S-2 (T)** 프론트 기동: `http://localhost:5173/` (패널리스트), `http://localhost:5173/researcher` (리서처) 동시 로드 확인.
- [ ] **S-3 (T)** 초기화: `POST http://localhost:4000/dev/reset` → `{ cleared: true }` (개발 모드 전용). 모든 계정·설문·응답·지갑·펫·레이트리밋·AI세션 비워짐.

### 1.2 패널리스트 시드 시나리오

- [ ] **S-4 (D)** 신규 가입 경로: 로그인(소셜 3종 중 1) → 온보딩 3스텝 → 부화. 기대: `welcomeBonus 500P` 적립, 펫 `알` 상태.
- [ ] **S-5 (D)** 데모 패널 pid: 리서처 데모는 `pid_demo_researcher` 사용(워크스페이스 `DEMO_PID`). 패널 통계/응답 흐름 체험에 쓰임.
- [ ] **S-6 (D)** 피드 채우기: 설문이 1건 이상 **라이브** 여야 덱에 카드가 뜬다. 리서처에서 "데모 설문 발행"(커피 취향 테스트) 실행 후 패널 피드 새로고침.
- [ ] **S-7 (D)** 데이터 조각 만들기: 설문 1건 완료 → `DataPiece` 1개 생성 → 정령 탭 "먹이기" 검사 가능. (조각은 24h 후 50% 보너스로 자동 소진됨 — 만료 분기 검사 시 참고)
- [ ] **S-8 (D)** 어뷰징 차단 재현: 응답 화면에서 **3문항 연속 즉시 응답(스피딩)** 또는 **4문항 연속 동일 선택지(직선응답)** → 3스트라이크 → `blocked` + 펫 `sick`. 10분 패널티.
- [ ] **S-9 (D)** 포인트 부족 재현: 잔액 < 상품가 상태에서 상점 "교환" 비활성('포인트 부족') 확인.
- [ ] **S-10 (D)** 관리 리서치 신청: 참여 탭에서 스터디 신청 → 리서처 관리 리서치에서 상태 전이(스크리닝→…→보상지급/미선정) 확인.

### 1.3 리서처 시드 시나리오

- [ ] **S-11 (D)** 빠른 시작 3종: 대시보드 빠른시작에서 ① 스튜디오 열기 ② 데모 설문 발행 ③ 응답 흐름 체험 — 순서대로 1회 실행해 칸반/분석에 데이터가 차는지 확인.
- [ ] **S-12 (D)** AI 초안: 설계 스튜디오에서 조사목적 입력(4자 이상) → "초안+검수 시작" → 문항/검수결과 생성. 심각(high) 1건 이상 만들어 발행 차단 분기 검사.
- [ ] **S-13 (D)** 발행 모달 경계값: 연령 min>max(오류), 도달<50명(차단), 정상범위(발행 가능) 3케이스 준비.
- [ ] **S-14 (D)** 분석/시맨틱: 설문 2건 이상 + 응답 다수 → 인사이트에서 KPI·분포·유사/중복 패널 데이터가 채워지는지 확인.

# PART F. UX/UI · 접근성 개선 (디자인 리뷰 대비)

> UX 전문가·UI 디자이너 관점 리뷰에서 도출. **이미 구현된 기반**(전역 `*:focus-visible` 링·`prefers-reduced-motion` 가드·`env(safe-area-inset-*)` 노치 대응·토스트 `role`/`aria-label`·다이얼로그 `role="dialog"`/`aria-modal`)은 양호로 확인됨. 아래는 실제 갭으로 검증된 항목만 추적한다.

- [x] **F-1 (A) 다이얼로그 키보드 접근성** — 모든 모달/바텀시트(`ConfirmDialog`·`PublishModal`·패널 `confirmExit`/`block` 시트)가 `aria-modal`만 있고 **Escape 닫기·포커스 트랩·포커스 복원 미구현**이었음 → 공용 훅 [useDialogA11y](../apps/frontend/src/lib/useDialogA11y.ts) 신설로 (1) 열릴 때 패널 내부 포커스 이동, (2) Escape로 닫기, (3) Tab/Shift+Tab 순환 트랩, (4) 닫힐 때 트리거로 포커스 복원 적용. **구현 완료**.
- [ ] **F-2 (U) 리서처 에러 배너 자동 해제** — `ResearcherWorkspace`의 `role="alert"` 에러 배너가 수동 닫기 전까지 영구 잔류 → 일정 시간 후 자동 소거 또는 잔여 타이머 시각화 검토.
- [ ] **F-3 (A) 상태 pill 색상 단독 의존 점검** — 설문 상태 pill(라이브/초안/종료)이 텍스트를 동반하는지 재확인하고, 색맹 사용자 대비 아이콘/라벨 보강 필요 여부 판정.
- [ ] **F-4 (U) 잔액 변경 알림** — 상단 `pm-balance` 값이 변동 시 스크린리더에 안내되도록 `aria-live="polite"` 보강 검토(현재 컨테이너 `aria-label`만 존재).
- [ ] **F-5 (A) 다크 모드** — `prefers-color-scheme: dark` 토큰 오버라이드 부재. 제품 우선순위에 따라 후속 과제로 분류.

> F-2~F-5는 추가 개선 백로그(우선순위: F-2·F-3 중간 / F-4·F-5 낮음). F-1은 이번 사이클에서 구현·검증 완료.
